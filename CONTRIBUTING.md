# Contributing to Kaizumi

Thank you for your interest in contributing to **Kaizumi**! We welcome contributions from developers, researchers, designers, and enthusiasts of all skill levels.

---

## Code of Conduct

This project adheres to the [Contributor Covenant](CODE_OF_CONDUCT.md). By participating, you are expected to uphold this code. Please report unacceptable behavior following our reporting guidelines.

## Development Setup

### 1. Prerequisites
- **Operating System:** Windows 10 or Windows 11 (64-bit)
- **Python:** Python 3.11, 3.12, 3.13, or 3.14
- **Git**
- **Hardware:** Microphone and audio output device (for live voice testing)

### 2. Fork and Clone
```bash
git clone https://github.com/<your-username>/kaizumi.git
cd kaizumi
```

### 3. Virtual Environment
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 4. Install Dependencies
```powershell
python -m pip install --upgrade pip
python setup.py
```

### 5. Configure API Keys
Copy the example templates (auto-generated by `setup.py`):
```powershell
# Edit config/api_keys.json with your free Gemini API key:
# https://aistudio.google.com/apikey
```

## Running the Test Suite

Before making any changes and before submitting a PR, ensure all tests pass:

```powershell
pytest tests -q
```

All 97+ unit tests run in memory without requiring a live Gemini API key or network access.

## Architecture Principles

When submitting changes, please keep Kaizumi's core design in mind:

1. **Centralized Safety Gate (`safety.py`):**
   - High-risk operations (file deletion, terminal command execution, killing processes, system shutdown) must be classified as `Risk.HIGH`.
   - Never add per-tool ad-hoc confirmation prompts. Extend `TOOL_RISK` and `_ACTION_RISK` in `safety.py`.
   - High-risk actions require verbal user consent and a single-use confirmation token (`confirm_token`).
2. **Deterministic Fallbacks:**
   - Tools must never hang indefinitely. Every tool executed in the live session is wrapped in `agent.resilience` with bounded timeouts.
   - If audio hardware is missing or disconnected, the application degrades gracefully to text mode instead of crashing.
3. **No Hardcoded Secrets:**
   - Never commit API keys, personal credentials, or local tokens. Ensure any sensitive keys are masked before logging or UI display via `safety.sanitize()`.

## Submitting Pull Requests

1. **Create a branch:**
   ```bash
   git checkout -b feat/your-feature-name
   ```
2. **Make your changes:**
   - Keep commits focused and logically grouped.
   - Add unit tests under `tests/` for any new logic or bug fixes.
3. **Run tests and formatting:**
   ```powershell
   pytest tests
   python -m compileall .
   ```
4. **Submit PR:**
   - Fill out the provided [Pull Request Template](.github/pull_request_template.md).
   - Describe what changed and include test verification.
